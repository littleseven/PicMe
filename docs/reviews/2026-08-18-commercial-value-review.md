> **文档编号**: REVIEW-COMMERCIAL-001

## 1. 市场事实：四条战线的调研结论

### 1.1 相册产品的付费轴：存储是唯一被反复验证的付费动机，AI 正在被巨头免费化

- **Google One** 订阅 1 亿（2024.2）→ 1.5 亿（2025.5），财报归因 AI 套餐拉动——但套餐本体是存储（$19.99/月含 2TB + Gemini）。[TechStartups](https://techstartups.com/2025/05/16/google-one-soars-to-150-million-subscribers-after-launching-ai-powered-plan/) Ask Photos 翻车重启后向用户**免费**开放，未单独收费。[Google 官方](https://blog.google/products-and-platforms/products/photos/updates-ask-photos-search/)
- **Apple Intelligence** 相册自然语言搜索/清理：免费、端侧+私有云计算，纯硬件卖点。[Apple Newsroom](https://www.apple.com/newsroom/2025/06/apple-intelligence-gets-even-more-powerful-with-new-capabilities-across-apple-devices/)
- **国内云相册**：一刻相册随心卡约 95-115 元/年、腾讯相册管家 SVIP 198 元/年 1TB——付费核心同样是**存储**。
- **含义**：PoLang 无云存储，切不进唯一被验证的主付费轴；而它最强的 AI 能力恰在被 Google/Apple **免费下沉**。"AI 功能直接收费"的假设没有先例支撑。

### 1.2 端侧/隐私定位：有可持续先例，但天花板明确在"小而美"

| 产品 | 模式 | 规模信号 |
|------|------|---------|
| **Ente Photos**（最接近 PoLang 的对标：E2EE + 端侧 ML 人脸/OCR） | 订阅 $9.99/月 1TB 五人共享 | 付费用户 12,018（2026.1）→ **19,490**，ARR $78 万 → **$125 万**，正增长 [ente.com/open](https://ente.com/open) |
| **Excire**（本地 AI 打标） | **买断 $249**，无订阅 | Excire Foto 2027（2026.6 发布）存活多年 [PhotoWorkout](https://www.photoworkout.com/excire-foto-2027-launch/) |
| **Immich**（自托管，ML 人脸/语义搜索） | 买断 license + FUTO 赞助全职开发 | 10.9 万 GitHub stars [immich.app](https://immich.app/blog/immich-joins-futo) |

- **含义**：隐私定位能养活小团队，但五年做到 $1.25M ARR 就是实证上限量级。值得注意的是**买断制（Excire $249）是被忽视的可行定价**——比订阅更适合"工具型隐私软件"的心理账户。

### 1.3 家庭照片共享：付费意愿已被验证，但"关系图谱"无人做、也无刚需证据

- **FamilyAlbum / みてね**（MIXI 2121.T）：全球 3000 万用户且仍在增长（半年净增约 800 万）[MIXI 官网](https://mixi.co.jp/en/news/)；所在分部 FY2026/3 收入 **171.6 亿日元（约 8 亿人民币，+16%）并首次扭亏**，增长引擎 = Premium 订阅（590 円/月）+ 照片冲印 + GPS 硬件 + 广告。[有价证券报告书](https://kitaishihon.com/company/2121/business) 人物 AI 仅"按孩子自动生成相册"（人脸聚类），**无通用关系图谱**。
- **亲宝宝**：约 5000 万家庭，家庭会员 298 元/年 + 母婴电商 + AI 硬件；自研育儿大模型押注育儿问答，**AI 完全不碰照片人物关系**。宝宝树 2024-12 强制退市——内容社区变现失败的反面样本。[36氪](https://m.36kr.com/p/3064705365435520)
- **Google Photos Partner Sharing**：2017 年起支持"仅自动分享含特定人物的照片"给一位伴侣——但只到"人脸分组 + 二元分享"为止。
- **含义**：家庭场景付费意愿真实存在（中日双市场验证），但**所有玩家的人物 AI 都停在"按人脸分组"**。"按亲属关系自动分发照片"这个位置客观空着——但必须诚实标注：**无证据表明它是刚需**，也可能"按人物分组"已覆盖 90% 需求，图谱只是 nice-to-have。这是本产品最大的单边赌注。

### 1.4 系统助手的挤压：实装全面，但边界清晰

- 已实装（非 PPT）：小米超级小爱"随心修图"（2025-11，相册内一句话修图）[快科技](https://news.mydrivers.com/1/1086/1086948.htm)；华为小艺修图智能体 + 智慧搜图 + HMAF 第三方接入框架 [华为官网](https://consumer.huawei.com/cn/support/content/zh-cn16070847/)；OPPO 小布自然语言找图；vivo 蓝心小 V 跨端编辑；Gemini 原生改图（2025-08）+ 嵌入 Google Photos。
- **边界：全部系统助手只操作自家系统相册，无一能进第三方 App 的数据层；无一家沉淀结构化人物关系数据。**
- **AppFunctions**（Android 16 API + Jetpack `@AppFunction`，"app 成为 on-device MCP server"）：已官宣、首个演示即相册场景，但仍为 experimental preview，调用权限仅特权助手可用。[9to5Google](https://9to5google.com/2026/02/25/android-appfunctions-gemini/) Apple WWDC26 官宣 Siri AI（iOS 27，跨 photos/messages 个人上下文），**首发仅英语 beta，中国大陆不可用**。[Apple](https://www.apple.com/newsroom/2026/06/apple-unveils-next-generation-of-apple-intelligence-siri-ai-and-more/)
- **含义**：2-3 年内系统相册+助手会吃掉"普通用户的找图修图"，第三方 App 只剩三块结构性空间：**跨平台一致性、端侧隐私、关系型数据资产**。AppFunctions 对 PoLang 短期是免费分发渠道（当渠道用，不当壁垒建）；注意接入即查询流经 Gemini 云端，与 [PRIVACY] 红线存在张力，需做"媒体不出端、文本元数据可出"的分层声明。

### 1.5 技术生态：开源输出有真实需求信号，但有先后

- **Koog**：1.0 于 2026-05 KotlinConf 发布（1 年 API 稳定承诺），stars 约 4.1k-4.4k，JetBrains 内部驱动 Junie/IntelliJ AI Assistant；tool_calls 丢帧是真实社区问题（[PR #1456](https://github.com/JetBrains/koog/pull/1456) 已合入），官方接受外部修复。Koog 是 **KMP 生态唯一全目标 agent 框架**，被 kotlinlang.org 官方推荐。
- **诚实修正**：PoLang 踩到的"历史裁剪 400""Android ServiceLoader 缺陷"未搜到公开 issue，**不能认定为普遍痛点**（可能属本项目特有场景）——开源叙事应以已验证的 tool_calls 修复与 KMP 双端接线模板为主。
- **MCP**：月 SDK 下载 9700 万（2026-03）；端侧已现 [droid-mcp](https://github.com/stixez/droid-mcp)（Android 本地 MCP server，2026-04）——方向被验证但已有先行者，且对方**没有写路径安全模型**（风险分级+用户确认），这正是 PoLang capability plane 的差异。
- **端侧人脸聚类**：Immich 用服务器端 InsightFace，社区在找替代方案；**移动端原生人脸聚类开源库为零**——空白最大但重资产（模型分发+精度评测维护）。
- **QuickJS KMP**：quickjs-kt 已覆盖底座，JS 沙箱不宜单独开源，应作为 capability 库的内置安全模型。

## 2. 商业价值判断

### 2.1 产品层：唯一自洽的商业故事

把四条战线的事实拼起来，PoLang 唯一自洽的定位是：

> **面向家庭的隐私优先相册管家——端侧人物关系是留存资产，"隐私 + 省心"是付费理由，Chat 是降低长辈使用门槛的交互层，AppFunctions/MCP 是免费分发渠道。**

- **付费锚**：订阅对标 Ente（家庭共享席位）或买断对标 Excire，**不做云存储**、不做"AI 功能费"。
- **核心叙事排序**：隐私（家人照片不出手机）> 省心（一句话找/发/整理）> 关系图谱（口碑传播点）。注意这个顺序与工程投入顺序相反——工程上图谱最重，商业上它只是增强件。
- **iOS 的隐藏红利**：Siri AI 缺席中国且首发仅英语，OEM 助手互不通用——**跨平台一致体验 + 中文家庭场景是系统助手结构性够不到的区域**，双端投入在商业上由此成立（此前只从 parity 工程角度论证过）。

### 2.2 技术层：声誉先行，反哺产品可信度

- 隐私定位的产品，**最强背书是代码可审计**——开源核心机制件不是情怀，是商业策略（Ente/Immich 均以此建立信任）。
- 修正后的开源优先级（结合生态调研）：**Koog KMP 生产适配件**（框架上升期 + 上游吸收通道 + 真实 issue 证据）→ **capability 权限门控框架**（KMP 生态空白 + droid-mcp 验证了需求但缺写路径安全模型，PoLang 有差异化）→ 人脸聚类移动端库（空白最大但重资产，后置）→ JS 沙箱不单列（并入 capability 库）。
- 技术声誉 → 隐私可信度 → 家庭用户转化，这条传导链是技术投入的商业闭环。

## 3. 迭代与取舍建议

### 3.1 立即做（0-4 周）：验证层，回答"有没有人要"

1. **家庭场景最小闭环测试版**：人物关系标注 + 一句话找/发照片 + PTT 语音，发给 50-100 个真实家庭用户（含长辈）。**这是所有推演唯一的定价方式。**
2. **度量自动化落地**：`llm_call_log`/`tool_call_log`/`js_run_log` 的分析层 + 留存/任务成功率埋点。没有它，测试版数据无法读。
3. **Koog 适配件开源**（复制+去包名级成本）：抢 Koog 1.0 生态早期窗口，同时给上游提 PR（有 #1456 先例）。

### 3.2 短期（1-2 月）：减负与工程化

4. **PTT 减负**：默认切系统 `SpeechRecognizer`，砍 Sherpa-ONNX 282MB 按需加载（留离线选项）——降低安装包体积对测试版转化有直接作用。
5. **iOS 互操作工程化**：SKIE spike + CrashKiOS 落地（欠账，见 KMP 评审行动项），为 iOS 测试版铺路。
6. **capability 契约严格化启动**：声明式 schema（风险分级/幂等性/权限），既是产品安全地基，也是开源框架的接口层。

### 3.3 中期（3-6 月）：渠道与定价实验

7. **AppFunctions/MCP 暴露评估与试点**：把只读能力（搜索/摘要）暴露给系统助手做分发；写操作暂缓（等标准权限模型明朗 + 隐私分层声明）。
8. **定价实验**：买断制 vs 家庭订阅 A/B（样本量小就用落地页预售测意愿，不建完整付费系统）。
9. **人脸聚类移动端库开源评估**：若测试版留存成立再启动（重资产，不与产品验证抢资源）。

### 3.4 明确不做（止损清单）

- ❌ 云存储/云同步（进入巨头付费轴主场，必败）
- ❌ 唤醒词投入、相机新功能（维持既有冻结决策）
- ❌ 与 OEM 拼计算摄影/生成式修图效果（军备赛，无胜算）
- ❌ 内容社区/电商化（宝宝树退市样本）
- ❌ 在测试版验证成立前，投入任何付费系统、会员体系、家庭共享服务端开发

### 3.5 Go / No-Go 决策点

测试版跑 4-6 周后，用预设阈值裁决（建议值，可调整）：

| 信号 | Go（继续投入） | No-Go（转纯开源/实验场定位） |
|------|--------------|---------------------------|
| 周留存 | 家庭单位 4 周留存 ≥ 30% | < 15% |
| 核心行为 | ≥ 40% 测试家庭完成过 1 次"关系标注 + 语音找图" | 关系标注完成率 < 10%（证伪图谱刚需） |
| 付费意愿 | 落地页预售转化 ≥ 3% | < 1% |

若 No-Go：项目退回"技术实验场 + 开源组合"定位（Koog 适配件 + capability 框架继续输出），这不是失败——按 AGENTS.md 的元实验定义，度量数据本身就是交付物。

## 4. 风险登记（本次调研新增）

1. **关系图谱刚需未证实**（最大单边赌注）：可能"按人脸分组"已覆盖 90% 需求。缓解：3.1.1 测试版把"关系标注完成率"列为核心观测指标。
2. **AppFunctions 渠道化风险**：交互界面归系统助手，App 有沦为后端的风险；且 UI automation 框架意味着不接入也会被零代码操控。缓解：只把渠道当增量，核心体验留在 App 内。
3. **隐私叙事 vs AppFunctions 张力**：接入即文本元数据流经 Gemini 云端。缓解：分层声明 + 默认关闭。
4. **开源叙事过度宣称**：历史裁剪 400 / ServiceLoader 坑无公开 issue 佐证，对外宣传时只讲可查证的部分，避免信誉损耗。
5. **小而美天花板**：Ente 五年 $1.25M ARR 是参照系——若按此定位，投入强度（尤其双端 parity 打磨）应与之匹配，避免按千万用户产品的方式烧钱。

---

## 5. 一句话总结

> **市场愿意为存储付钱（你没有）、为隐私付小钱（Ente 已验证）、为家庭省心付钱（Mitene 已验证）——PoLang 的商业故事只能从后两者拼出来；人物关系图谱是无人区也是单边赌注，用一个 50-100 家庭的测试版在 6 周内给它定价，Go 则 All-in，No-Go 则退回实验场定位、以 Koog 适配件和 capability 框架收割技术声誉。**
