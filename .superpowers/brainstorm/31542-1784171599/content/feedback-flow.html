点击反馈后，系统怎么响应？

本地持久化已确认。现在确定 👍 / 👎 / 🔁 触发后的结果流转方式

A

静默重排

👍/👎 只更新后台权重，当前卡片顺序立即微调；不发送新消息，不触发搜索。

  • 实现最简单，UI 即时响应
  • 用户可能感知不到“系统在学”
  • 🔁 需要单独处理成“再找一些类似的”
B

Agent 主动推进下一轮

任何反馈都触发 Agent 生成新查询，返回一条新的“找到了 X 张你可能更喜欢的…”卡片消息。

  • 多轮对话感最强
  • Agent 可解释推荐原因
  • 每次反馈都走 LLM，成本高、延迟大
C

分层响应

👍/👎 先静默更新权重并重排当前卡片；🔁 或连续多个反馈后再触发 Agent 返回下一轮结果。

  • 低成本 + 可解释性兼顾
  • 控制节奏：反馈积累到阈值才调用 LLM
  • 规则稍复杂，需要状态机
